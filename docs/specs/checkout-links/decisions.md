| Q2 | Does a link add to the buyer's cart or open checkout on its own? | It adds its items to the buyer's cart and opens checkout. | Q4 | Where does opening a link add its items, given the cart lives on the buyer's device (`src/store/cartStore.ts`) and a guest has no server cart? (departs from TRD D3) | `/c/<shop>/<token>` is a page: it resolves the link on the server (edited → the shop's page, expired → the first product's page with the line) and otherwise renders checkout's skeleton while `POST /api/checkout-links/open` returns today's lines and the device adds them, marked, then opens checkout. The once-only claim is `CheckoutLinkOpen(linkId, cartKey)` with `cartKey` `user:<id>` or `device:<id>` (an httpOnly `bb_device` cookie), not a server cart id. The rate limit sits on the open request (`link` policy, per account or address), and the page is not in `EXTERNALLY_CALLED`, which lists route handlers only. A refused or failed open goes to the shop's page. The page itself is not rate-limited: it only says whether a 128-bit token exists, a search no budget changes. What was left out is not carried to checkout: unit 2 recomputes it from the link's stored items against the lines marked with it | Claude · reversible | 2026-11-25 | A route handler cannot write the device cart, and writing the signed-in server cart behind the device's back would conflict with its version and reach a guest not at all. was: TRD D3 "one transaction adds the items to the buyer's cart (guest cookie or account)" | implemented (unit 1) |
| Q5 | What does a link add for an item that is in stock but not at the asked quantity, or already in the cart? | Not at the asked quantity → left out and named, like an item out of stock (the check `/api/products/check-stock` makes). Already in the cart → the line keeps the larger quantity and takes the link's mark, never doubled | Claude · reversible | 2026-11-25 | The spec names only out-of-stock; one rule for both, and no silent quantity change. Taking the larger quantity keeps a second device or a sign-in from adding the link twice | implemented (unit 1) |
| Q6 | An expired link for several products opens which page? | The first product still on sale, with the expired line; none on sale → the shop's page | Claude · reversible | 2026-11-25 | A redirect opens one page; the first item is the one the chat was about | implemented (unit 1) |
| Q7 | Which link items does checkout call "out of stock and left out"? | Those neither among the checkout's lines marked with the link nor addable now (on sale, not held by an auction, in stock at the quantity), recomputed by `POST /api/checkout-links/notes`. A price change is shown only against the snapshot of that exact product | Claude · reversible | 2026-11-25 | Q4 left the left-out list for unit 2 to recompute; "not in the checkout" alone would call a line the buyer removed out of stock | implemented (unit 2) |
| Q8 | How does a link say "the buyer picks the size", and what are the sizes? (TRD D6) | A link item may carry `pickSize`. The step offers the item's family members on sale and in stock at the quantity, named as the product page names its siblings (by product name); a pick not among them is ignored and the link's own item is added. A product in no family has no step; an item with no size in stock has no step and is left out like any other. The size-price snapshot covers every member, so "was ₹y" is the picked size's own | Claude · reversible | 2026-11-25 | A family's members differ by facts, not one size field, and the product page already lists siblings by name; the pick is re-checked on the server because the address can be edited | implemented (unit 2) |
| Q9 | Which order does a link record when the buyer tries to pay twice? (TRD D5) | The latest order placed through it, until one is paid; a paid order is never replaced. Only a link of the shop the line was bought from, on a line holding one of the link's products (or a size of one), is recorded. A link forwarded to several buyers keeps one order: if a second buyer's unpaid order replaces the first's and the first then pays, the link names the second. Accepted: a link is made for one buyer (spec), and nothing is reported from it yet (Q3). The "paid" check reads checkout's `PAYMENT_STATUS`, a type import cart takes back from the domain that calls it | Claude · reversible | 2026-11-25 | Each Pay makes a new order, so "first order wins" would keep an abandoned one; the shop check stops a line naming another shop's link | implemented (unit 2) |
| Q10 | What does opening a link do when nothing in it can be added? | Shows "Everything in this link is out of stock now." with the items' names beneath and Visit shop on the link page, and claims nothing, so the link adds its items once they are back | Claude · reversible | 2026-11-25 | ux.md's All out of stock row; claiming an open that added nothing would make the link useless after a restock | implemented (unit 2) |
