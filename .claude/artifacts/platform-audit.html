Buyer Surface

What's solid

The core purchase flow works end-to-end: browse, search, add to cart (guest or signed in), checkout with address + shipping + coupon, pay via Razorpay, receive confirmation email, view order. Wishlist, reviews with photos, bidding with live countdown, share dialog, contact via email/WhatsApp — all complete.

What needs fixing

Orders page shows no tracking or fulfilment status

Tracking fields (AWB, courier, tracking URL, estimated delivery) exist in the database and admin enters them, but the buyer order detail page doesn't display them. Buyer also can't see whether their order is processing, packed, shipped, or delivered.

No order cancellation or return/refund flow

REFUNDED status exists but nothing exposes a cancellation or return request to buyers.

No auction listing page

Buyers can bid on /bid/[slug] but there's no page showing all ongoing and upcoming auctions.

Toast has no close button

One-line fix: add closeButton to the <Toaster> in providers.tsx.

Bill download is browser print, not a real invoice

No generated PDF, no GST/tax breakdown, no invoice number.

Search has no filters and no full-text search

Just a Prisma contains (LIKE) on product name. No category filter, no price range, no sort on search results.

Seller Surface

What's solid

Org creation, product CRUD (with dynamic facts from product type), stock per location, offers with date/usage/conditional controls, bidding, earnings ledger, media library with AI enhancement, storefront editor with 9 sections and hide controls, promotional banners. The product form is not the "old" one — it has category-driven facts, measurements, family assignment, and the full pricing/gallery/inventory stack.

What needs fixing

Org profile is confusing to complete

The standing panel (your second screenshot) shows 5 sections as "Waiting" but the labels are unclear about what exactly is needed. "Waiting on at least one block, with a heading and a line under it" for "How you work" is jargon. The storefront editor could guide the seller step by step instead of dumping all fields at once.

Product families have no standalone management page

A family can only be created from inside the product form. No way to edit a family's shared facts, measurements, or description after creation without editing a member product.

Product flags are all manual

ON_OFFER should be derived from active promotions. NEW_ARRIVAL should be derived from creation date. Only FEATURED and HERO make sense as manual flags. CLEARANCE_SALE should pair with an offer.

Seller orders are read-only with no search

Seller can't update fulfilment status (processing → packed → shipped), can't search orders, can't filter by status or date.

Seller can't respond to reviews

Reviews are read-only. No seller-reply mechanism.

No feature gating for free vs paid sellers

You want the storefront locked for free sellers, plus limits on channels, image enhancer, social posting. There's zero subscription infrastructure to gate anything.

Admin Surface

What's solid

Categories (CRUD + bulk + hierarchy), banners, promotions with clash handling, bidding monitoring with outcome recording, payouts with commission/settlement, reviews moderation (3-state), enhancements management with per-org controls, channel mapping dictionary. All server-rendered with URL-driven filters.

What needs fixing

Users page is a dead end

List exists but rows aren't clickable. No user detail page — no profile view, order history, activity log, or address list for any user.

Organizations page is modal-only and shallow

Oldest-style admin page. No detail page, no org stats, no product/order/member view from admin side. Delete exists (may violate ADR-0020/0032). Still a "use client" component.

Dashboard has placeholder data

getTopProducts returns featured products with salesCount: 0. Revenue chart code exists but is never rendered. No auto-refresh.

Admin can't archive policy-violating products

Products tab is read-only for admin. Archiving is org-only.

Product Types and Media not in sidebar

Both exist and work but aren't in the sidebar nav — reachable only by direct URL.

Shipping is manual end-to-end

Admin creates shipment on Shiprocket website, then manually enters tracking details. No API booking, no auto-scheduling, no label generation, no pickup scheduling.

Abandoned carts are view-only

No automated recovery emails or follow-up workflow.

Your Questions Answered

How do we decide "best selling products" on the storefront?
Currently we don't. getTopProducts is a placeholder — it returns featured products with salesCount: 0, revenue: 0. The comment in the code admits "Would need to calculate from orders." To make it real: query OrderItem grouped by productId, sum quantities, filter by org and time window. Stars don't factor in — best selling means most purchased.
What does the accent color actually do?
It works. StorefrontTheme wraps the storefront in data-accent="..." and CSS remaps --primary and --ring tokens. It colors the identity bar, buttons, and focus rings inside the storefront only — navbar/footer stay platform-colored. The limitation: only 3 non-default choices (success=green, warning=amber, info=blue). "primary" is the default, not a distinct pick. If you want the accent to also affect background lighting or fonts, that's new work.
Where do we put family details? There's no form for it.
Correct. A family can be created inline from the product form (just a name + description), but there's no standalone family management page to edit shared facts, measurements, or variant axes after creation. The data model supports it (ProductFamily has facts, measurements, variantAxis fields), but there's no UI to manage them independently.
Do we need connections to Google and Meta to sell there, or does listing on BB auto-enlist?
It does not auto-enlist. Google Shopping and Meta are "shopfront" channels — they work by fetching a feed file (XML/CSV) from your site. You generate the feed, submit the URL to Google Merchant Center / Meta Commerce Manager, and they index it. This is different from Amazon/Flipkart which need direct API integration. So: you need to build feed generation (the shopfront-feeds spec in the backlog), but not a real-time API connector. The channel readiness system already tells you if products are ready for each platform.
Product flags — are any derived?
All 5 are manual. ON_OFFER should auto-set when a promotion covers the product. NEW_ARRIVAL should auto-set based on creation date (e.g. last 30 days). CLEARANCE_SALE should pair with a deep-discount offer. Only FEATURED and HERO make sense as manual seller-chosen flags.
Channels tab — what does it do?
It's the channel-mapping dictionary. When you eventually publish to Amazon, you need to translate "our product type = Abaya" into "Amazon category = Ethnic Wear > Abayas", and "our fact key = material" into "Amazon attribute = material_type". The channels tab is where admin builds this translation dictionary. It also shows what's still unmapped. It's pre-publishing infrastructure, not a live integration.
How incomplete is the listing phase (phase 11)?
The foundations are done (60% by spec count): product types, facts vocabulary, families, channel mappings, readiness engine, channel register — all implemented and working. What remains is the integration layer: feed generation, marketplace connectors, publishing, inventory sync, channel reporting, Instagram posting. These 6 items have no specs yet. The phase is "dictionary complete, no one speaks the language yet."

Loopholes Found

Security & data integrity

Admin org delete may violate ADR-0020 and ADR-0032

DELETE route exists for orgs. Money-bearing records (orders, ledger entries) reference the org. Deletion should be refused; the operation is deactivation. Uses confirm() browser dialog instead of a proper confirmation.

Console.log debug statements left in cartStore.ts

Lines 121-134 have debug logs that ship to production.

Dead CartService interface in src/domain/cart.ts

Unreachable code.

UX violations of project rules

Checkout button disabled when cart is empty (ADR-0053)

"Never disable a button" — it should stay enabled and explain why checkout can't proceed.

Location delete button disabled instead of explaining (ADR-0053)

Uses disabled button + title tooltip when a location has stock. Should keep the button enabled and show a message on click.

Missing enforcement

payments → checkout cross-domain violation

Payments writes directly to checkout's order repository. Allowlisted in the boundary test but needs checkout to expose a confirmPaid command.

Product.weight has a leftover "// ADD THIS:" comment in schema

Task artifact in production schema.

New Features Assessment

Subscription tiers (1, 3, 6, 12 months)

Build from scratch

Zero infrastructure exists. Needs: Plan/Subscription/Invoice models, Stripe integration (type declared, nothing built), recurring billing, metering, feature-gate middleware, upgrade/downgrade/cancel flows, grace period handling. This is the biggest new feature and should come first because everything else (channel connectors, social posting, enhancement quotas) gates on it.

Auto delivery scheduling

Extend existing shipping domain

Shiprocket integration exists for rates + tracking. The stub mock.booking.ts is ready for real booking. Needs: API-based shipment creation (Shiprocket has the API), auto-trigger on order confirmation, pickup scheduling, label generation. The provider interface is already designed for this.

Flipkart & Amazon integration

Large project with external dependencies

Needs: OAuth/credential management per seller, API adapter per platform (SP-API for Amazon, Flipkart Seller API), listing push, order import, stock sync, return handling. Each platform is ~4-6 weeks of work. The readiness system and channel mappings are already built as the foundation.

Google & Meta integration

Feed-based, simpler than marketplaces

Generate a product feed file (Google: XML per Merchant Center spec, Meta: CSV per Commerce Manager spec). Host it at a public URL. Sellers register the URL with Google/Meta. No real-time API, no order import. ~1-2 weeks once the feed generator is built.

Instagram posting

Moderate — needs Meta Graph API

Generate a post draft (image + caption from product data), publish via Instagram Graph API (requires Facebook Business account + long-lived token per seller). Gated behind subscription.

Recommended Order

Three tiers. Each tier's items are independent within the tier and can be parallelized.

Tier 1 Fix what's broken (before adding anything new)
  • Buyer orders: show tracking info + fulfilment status on order detail
  • Toast close button: add closeButton prop (5-minute fix)
  • Admin users page: make rows clickable, add user detail page with order history
  • Admin orgs page: replace modal with detail page, remove delete route, add deactivate
  • Admin dashboard: wire up top products from orders, render the revenue chart
  • Admin products: add archive action for policy violations
  • Admin sidebar: add Product Types and Media to nav
  • Seller orders: add search/filter, allow seller to update fulfilment status (at least packed/shipped)
  • Product flags: derive ON_OFFER and NEW_ARRIVAL; keep FEATURED and HERO as manual
  • Disabled buttons: fix checkout button and location delete to follow ADR-0053
  • Docs: add listing domain to README, ARCHITECTURE; fix spec headers; write server/listing/CLAUDE.md
  • Cleanup: remove console.logs in cartStore, dead CartService, schema comment
Tier 2 Complete the product (makes it a sellable platform)
  • Subscription & billing: Stripe integration, plan models, feature gates — this unlocks everything below that needs gating
  • Auto delivery scheduling: extend Shiprocket integration to API-based booking + pickup scheduling
  • Auction listing page: a /auctions page showing all ongoing/upcoming events
  • Product family management page: standalone CRUD for families outside the product form
  • Buyer order cancellation: cancel flow + refund initiation
  • Invoice generation: proper PDF with GST breakdown and invoice number
  • Seller review replies: let sellers respond to reviews
  • Search improvement: pg_trgm or full-text search, add filters (category, price, sort)
  • Abandoned cart recovery: automated email sequence
  • Org profile UX: guided setup wizard instead of a wall of fields
  • Best selling products: compute from orders, show on storefront
  • Accent color: either add more presets or allow custom hex
Tier 3 Expand the platform (marketplace integrations)
  • Google Shopping + Meta feeds: generate XML/CSV feeds from product data + channel mappings
  • Flipkart connector: OAuth, listing push, order import, stock sync
  • Amazon connector: SP-API, listing push, order import, stock sync
  • Instagram posting: draft generation + publish via Graph API
  • Channel reporting: consolidated cross-channel sales view
  • Inventory sync: real-time stock reconciliation across all channels
  • Return/refund flow: buyer-initiated, with gateway refund

Summary: Tier 1 is fixing what exists — mostly UI gaps and admin pages that need detail views. Tier 2 is making the platform complete enough to charge for — subscription billing is the gate. Tier 3 is the marketplace expansion that makes the listing phase vocabulary pay off. Don't start Tier 3 until subscription billing is live, because every connector needs a subscription gate.
